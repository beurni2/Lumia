Purpose:
P11-T3 root-cause audit proved FOOD_V2 / widened-edge entries are not shipping because they are never attempted.

Root cause:
- T2 projection widening increases matching[] to 80–167 candidates per core.
- FOOD_V2 entries are appended at the tail of NIGERIAN_HOOK_PACK.
- matching[] preserves pack order.
- salt rotation is too narrow in practice.
- NIGERIAN_PACK_ELIGIBLE_DRAW_CAP=12 closes before FOOD_V2 / T2-only projected entries are reached.
- Therefore widened entries never enter authorPackEntryAsIdea, passing[], retention, or slot reservation.

Important conclusion:
This is NOT a corpus quality issue.
This is NOT a validator issue.
This is NOT a ranker issue.
This is NOT a memory issue.
This is NOT a topK retention issue.
The problem is lack of attempt budget for T2-only projected entries.

Goal:
Implement a small projection-aware attempt budget inside the existing Nigerian pack attempt loop so T2-only projected entries get attempted when the T2 flag is active.

Definition:
A “T2-only candidate” is a pack entry that matches the current core because of a T2 overlay projection, not because of the legacy PACK_DOMAIN_MAP projection alone.

Current T2 overlay:
- everyday → mornings
- everyday → sleep
- home → food

Implementation guidance:
Inside coreCandidateGenerator.ts near the pack matching / drawCap loop:

1. Preserve existing matching behavior.
2. Compute legacy projections and T2 overlay projections separately.
3. Classify candidates into:
   - legacyMatch candidates
   - t2OnlyMatch candidates
4. Preserve the existing legacy attempt path.
5. Add a small independent T2-only reserved attempt slice when T2 flag is ON.

Preferred budget:
- 12 legacy attempts preserved
- plus up to 3 T2-only attempts
- total max attempts = 15
- do NOT reduce legacy attempts from 12 to 9
- if no T2-only candidates exist, behavior should remain legacy-only

Important:
Apply deterministic salt rotation independently to the T2-only candidate slice.

Do NOT always take the first 3 T2-only candidates.
Use the same kind of deterministic rotateBy pattern:
- rotateBy = deterministic salt % t2OnlyOrdered.length
- ordered = rotated slice
This prevents creating a new T2 mini-monoculture.

Avoid duplicate attempts:
- if a candidate appears in both legacy and T2-only pools, attempt it once only
- by definition T2-only should exclude legacy matches, but still guard against duplicates
