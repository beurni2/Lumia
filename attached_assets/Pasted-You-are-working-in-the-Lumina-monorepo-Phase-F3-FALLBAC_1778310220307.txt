The F3 fallback root-cause audit is accepted.

Root cause:
The 45s timeout is a symptom, not the core issue. The fallback path is currently structured as a full-batch rebuild and is triggered on `guards_failed` even when the local pool is already complete. In F3, localKept was far above desiredCount, fallback still triggered, Claude was asked for the full desiredCount=10, timed out, and local best-effort shipped anyway. Result: ~50s latency tax, 0 fallback ideas served.

Goal:
Implement the smallest safe fix recommended by the audit:

Make fallback fire on `guards_failed` only when there is an actual local-pool gap.

Do not change prompts.
Do not change model/provider.
Do not change timeout.
Do not change corpus.
Do not change validators.
Do not loosen gates.

Implement Option F:

When fallback reason would be `guards_failed`, only set `needFallback = true` if:
