PHASE W2-R — Memory + Diversity Control + Optional Taste-Gated Deterministic Variation

Objective:
Improve the real creator experience after W2-O / W2-P / W2-T / W2-V by making Western/clean idea refreshes feel fresher, more diverse, more human, and less repetitive across batches.

This is NOT a corpus-expansion phase.
This is NOT a W2-O redo.
This is NOT a provider/Claude/prompt phase.
This is NOT a generic “memory architecture” project.
This is NOT a random variation engine.

The product goal:
Every batch should feel like a funny human creator with taste selected three different, filmable ideas — not like a system is recycling the same joke shape.

Current state:
- W2-O live pool architecture is GO.
- W2-P repair/live closeout is GO.
- W2-T diversity batch is integrated.
- W2-U2 polish is GO.
- W2-V exposure diagnosis is GO.
- WESTERN_HOOK_PACK_LIVE = 355.
- W2-T exposure is healthy:
  - W2-T = 26.3% of W2 picks.
  - refresh-only W2-T = 29.5%.
- Source mix is healthy:
  - W2-I = 30.1%.
  - W2-L = 24.7%.
  - W2-T = 26.3%.
  - W2-N = 18.8%.
- In-batch duplicate failures = 0.
- Claude fallback ≈ 1%.
- Production W2 remains OFF.
- The W2-T “missing exposure” issue was a smoke-harness classifier bug, not a runtime selector defect.
- Do not implement W2-T source-mix fixes.

Main remaining product concern:
Even with a strong 355-entry live pool, the experience can still feel repetitive if refreshes repeatedly surface similar:
- anchors
- settings
- hook skeletons
- comedy families
- hook styles
- phone/screen-led vibes
- desk/productivity vibes
- support-copy templates
- first-batch W2-I-heavy patterns

W2-R goal:
Use existing memory and deterministic scoring overlays to improve:
1. cross-refresh novelty
2. in-batch diversity
3. creator-specific recent-exposure suppression
4. first-batch and refresh-depth variety where safe
5. support-copy freshness only if it can stay human/tasteful

Hard rules:
- Do not change production flags.
- Do not enable W2 in production.
- Do not loosen validators.
- Do not change ideaSchema.
- Do not change Claude prompts.
- Do not increase Claude usage.
- Do not add migrations unless explicitly approved.
- Do not add new database tables.
- Prefer existing JSONB / existing creator memory fields if persistence is needed.
- Do not change Nigerian/Pidgin/N1 behavior.
- Do not change India/Philippines behavior.
- Do not redo W2-O.
- Do not import another batch.
- Do not hard-force W2-T quota.
- Do not weaken anti-repeat / anti-copy gates.
- Do not make random or non-deterministic selection changes.
- Do not ship any change that makes ideas feel more automated, templated, generic, or less human.
- Quality/taste beats novelty mechanics.

Important product standard:
The ideas, hooks, scenarios, captions, howToFilm, and Film This Now guidance must feel human, creator-native, realistic, funny, and filmable.

Do not optimize for mechanical diversity if the result feels worse.
Do not add “clever” automation that creates generic output.
Do not vary hooks or scenarios in this phase.
Do not touch the core premise of any curated idea.

Required first step:
Before editing app logic, produce W2-R diagnosis and baseline reports.

TASK 4 — Implement Minimal W2-R Only If Baseline Shows Real Issues

Do not implement architecture for its own sake.

If the baseline shows refresh diversity is already strong enough, stop and recommend no-op.

If the baseline shows meaningful repetition, implement the smallest safe change.

Preferred implementation shape:

A. Recent Exposure Ledger Overlay

Use existing memory structures where possible.

Track recent:
- westernPackEntryId
- runtime telemetry id if needed
- sourceBlock
- hook
- normalized hook skeleton
- anchor
- setting
- comedyFamily
- emotionalSpike
- hookStyle
- contentType / filming mode if available
- timestamp or batch depth
- whether idea was shown / selected / opened / copied if already available

Rules:
- Do not create a new DB table.
- Do not add a migration unless explicitly approved.
- If persistence already exists in creator JSONB, extend it additively.
- If only in-process demo memory exists for unauthenticated demo creators, preserve and document that behavior.
- Must parse old memory documents safely.
- Must default to empty arrays for older creators.
- Must cap stored history to a reasonable size.
- Must not break existing creator records.

B. Cross-Refresh Penalties

Add deterministic soft penalties for recently seen dimensions.

Recommended behavior:
- same entryId: hard reject or very strong penalty.
- same exact hook: hard reject or very strong penalty.
- same hook skeleton: strong penalty.
- same anchor: medium penalty.
- same setting: medium penalty.
- same comedyFamily: medium penalty.
- same hookStyle: light penalty.
- same source block repeatedly: light penalty only if source imbalance is observed.

Important:
- Do not hard-ban quality winners except exact entryId / exact hook.
- Use soft penalties so strong ideas can still win when alternatives are weak.
- Do not punish first-session quality too aggressively.
- Do not create a W2-T quota.
- Do not weaken existing anti-copy/anti-repeat validators.

C. In-Batch Diversity Guard

When selecting 3 ideas:
- no duplicate entryId
- no duplicate hook skeleton
- no duplicate anchor
- avoid same setting 3/3 if alternatives exist
- avoid same comedyFamily 3/3 if alternatives exist
- avoid all phone/screen-led 3/3 if alternatives exist
- avoid all desk/productivity 3/3 if alternatives exist
- preserve max 2 W2 ideas / batch if that is still the intended W2-K2 rule
- if the second W2 is not distinct enough, fill with old/core idea rather than forcing repetition
- quality must still win over artificial variety

D. First-Batch Diversity Nudge — Optional

The W2-V probe showed first batch is 100% W2-I because of startIdx=0 / top-of-pool ordering.

Do not “fix” this unless baseline shows first-batch quality/diversity is actually poor.

Allowed minimal fix if needed:
- soft diversity nudge within already-eligible first-batch candidates
- no hard source quota
- no W2-T forced first-card
- no quality/rubric bypass
- no memory regression
- must preserve strong first impression

Do not over-optimize source distribution if the visible ideas already feel diverse and great.

E. Deterministic Variation — Optional, Taste-Gated, Support-Copy Only

Do NOT implement deterministic variation unless the diagnosis shows repeated product-facing copy is hurting the refresh experience.

Do NOT vary hooks in W2-R.
Do NOT vary WHAT TO SHOW in W2-R.
Do NOT create new premises.
Do NOT use Claude or random LLM rewriting.
Do NOT generate generic alternate wording.

Allowed deterministic variation surfaces only if implemented safely:
- captions
- howToFilm phrasing
- Film This Now copy
- comfort-mode tips
- text overlay suggestions

Quality bar:
Every variant must sound hand-written, creator-native, specific, funny, and clear.
If a variant sounds generic, templated, overly clever, confusing, or AI-ish, it should not exist.

Rules:
- deterministic seed = creatorId + entryId + batchDepth or regenerateSalt.
- preserve hook.
- preserve anchor.
- preserve whatToShow.
- preserve safety note.
- preserve core scenario.
- preserve comedyFamily / emotionalSpike.
- preserve filmability.
- pass validators.
- no new safety risk.
- no hook-length risk.
- no abstract “vibe” rewrites.
- no “make it more creative” generation.

Implementation preference:
Start with memory and diversity control first.
Only add deterministic variation if it is backed by hand-authored variant templates and tests.
If the implementation would produce lower-taste copy, defer it.
