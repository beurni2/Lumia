Phase W2-K2 — Western 2-of-3 Authored Delivery + Memory/Selection Fix

Context:
W2-K staging showed the approved Western pool can enter Western/default generation and non-Western leak gates are clean, but the activation behavior is not ready.

Observed W2-K issues:
- W2 ON western: 10/10 batches had W2 ideas.
- W2 ideas total: 20/30, meaning W2 was already delivering 2/3.
- 10/10 batches had ≥2 W2 ideas.
- 0 batches had 3/3 W2, which is good.
- But only 15 distinct W2 entryIds appeared across 20 W2 ideas.
- Cross-batch hook repeats occurred 5 times.
- W2-OFF baseline did not run.
- Post-review hookQualityScore meta bug was fixed and must be preserved.

Updated product goal:
Western/default should usually ship:
- 2 W2-authored ideas per 3-card batch
- 1 old-corpus / pattern / novelty idea per batch

W2 should become the main Western quality layer, but not the only source. The old corpus must remain active for breadth, fallback, novelty, and personalization.

This phase is about fixing W2 memory/selection quality before more corpus expansion.

Primary goal:
Make 2 W2 ideas per Western/default batch work without repeats.

Required behavior:
1. Target 2 W2 ideas per 3-card Western/default batch when enough distinct W2 candidates are available.
2. Keep 1 non-W2 idea in each batch for breadth/novelty.
3. Do not ship 3/3 W2 by default.
4. If W2 memory/dedupe blocks too many candidates, fall back to 1 W2 + 2 old-corpus rather than repeating W2.
5. Do not repeat W2 entryIds across recent refreshes.
6. Do not repeat exact W2 hooks across recent refreshes.
7. Do not repeat normalized W2 hook skeletons across recent refreshes.
8. Avoid repeating the same W2 anchor too often.
9. Avoid repeating the same W2 comedyFamily too often.
10. Avoid repeating the same W2 setting too often, especially bedroom/desk.
11. Do not allow two W2 ideas in the same batch with the same anchor.
12. Do not allow two W2 ideas in the same batch with the same normalized skeleton.
13. Prefer two W2 ideas only when they are clearly distinct across:
    - entryId
    - hook
    - skeleton
    - anchor
    - comedyFamily
    - emotionalSpike
    - setting

Memory approach:
Use the no-migration path first.

Derive recent W2 memory from existing persisted recent batch data / creators.last_idea_batch_json if possible.

Track:
- recent W2 entryIds
- recent exact hooks
- recent normalized hook skeletons
- recent anchors
- recent comedyFamily values
- recent emotionalSpike values
- recent settings

If W2 entryIds are not recoverable from last_idea_batch_json:
- Add internal/staging-only telemetry needed to verify W2 entryId behavior.
- Do not add a DB column in this phase.
- Do not silently relax the “no repeated W2 entryId across recent refreshes” gate.
- Report exactly what is missing and stop before implementing a weaker version.

Selection requirements:
- Do not simply sort by score and repeatedly pick the same top W2 entries.
- Add selection pressure for underused W2 entries.
- Penalize recently seen W2 entryIds strongly.
- Penalize recently seen W2 hook skeletons strongly.
- Penalize repeated anchors/comedyFamily/settings softly.
- Keep hookQualityScore and existing quality scoring meaningful.
- The picker should use more of the approved pool over repeated refreshes.

Suggested W2 selection shape:
1. Build eligible W2 candidate pool from APPROVED_WESTERN_PROMOTION_CANDIDATES.
2. Remove or hard-penalize recently seen entryIds / exact hooks / skeletons.
3. Apply soft diversity penalties for recent anchor, comedyFamily, emotionalSpike, setting.
4. Select first W2 card by strongest adjusted score.
5. Select second W2 card only from candidates distinct from the first across skeleton and anchor, preferably family/spike/setting too.
6. Fill the third card from old corpus / pattern / novelty path.
7. If second W2 is not distinct enough, ship 1 W2 + 2 old-corpus instead of forcing a weak or repetitive W2.
