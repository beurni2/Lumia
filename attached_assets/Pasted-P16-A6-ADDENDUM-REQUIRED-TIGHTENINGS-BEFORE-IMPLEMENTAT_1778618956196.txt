2. Suppression mechanism must be post-rank filtering, not score demotion

Do NOT modify hookQualityScore.
Do NOT apply score penalties.
Do NOT change scorer math.

Implementation should be:

- build the normal ranked slot-1+ clean-core candidate list exactly as today
- filter out IDs recently seen in nigerian_clean_core_slot1plus_seen_ids_json
- select from the filtered list
- if filtering leaves fewer candidates than needed, gracefully relax by falling back to the original ranked list for remaining slots

This keeps scorer behavior untouched and makes the anti-repeat guard local to slot-1+ selection.

Report:
- IDs filtered
- whether relaxation happened
- IDs selected after filtering
- final emitted slot-1+ clean-core IDs

3. Regenerate behavior

Slot-1+ memory must apply to regenerate flows.

Reason:
Regenerate is exactly when the user expects fresh hooks, not the same trailing clean-core entries again.

Required behavior:
- On normal generation: consult slot1+ memory before selecting slot-1+ clean-core entries.
- On regenerate: also consult slot1+ memory.
- On successful normal generation: write emitted slot-1+ clean-core IDs to slot1+ memory.
- On successful regenerate: also write emitted slot-1+ clean-core IDs to slot1+ memory.
- If generation fails or underfills and is not committed/emitted, do not write speculative IDs.

If the repo distinguishes preview/dry-run/test generation from committed user-visible generation, only committed/emitted ideas should update persistent memory.
