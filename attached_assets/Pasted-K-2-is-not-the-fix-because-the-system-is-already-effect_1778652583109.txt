K=2 is not the fix, because the system is already effectively beyond K=2. The report says NIGERIAN_PACK_AWARE_RETENTION_TOP_K = 11 is already enabled, meaning the pack branch can retain up to 11 distinct pack candidates per core. So widening from K=1 to K=2 is moot; the runtime already has a much wider retention layer than that. 
What the audit proves
The light-pidgin pool is healthy:


263 / 264 eligible light-pidgin pack entries.


40 / 40 audited cores have at least one pack candidate.


40 / 40 have at least two pack candidates.


Average passing pack candidates per core: 101.5.


Rank #1 vs #2 are always distinct entry IDs and distinct hook texts. 


So the problem is not “not enough candidates” and not “K=1.”
The real issue is that the same few high-scoring entries dominate across many cores:


ng_82b4bff9 — airtime


ng_c15c7a96 — gate


ng_d995c073 — light


ng_950aceff — mute


ng_41f376c1 — charger


Those appear repeatedly as rank #1–#5 across many different premise cores. That means even with K=11, the downstream reservation still keeps seeing the same high-score cluster.
Supervisor decision
Do not implement “K=2 widening.” It is outdated.
The next fix should target cross-core pack winner monoculture, not per-core candidate count.

Do not change the hook scorer.

Why salt tie-break alone may be insufficient now
Salt tie-break helps when #1 and #2 are near-tied. The audit shows that does happen often: 33 / 40 cores have #2 within 5 points, and 20 / 40 within 2 points. 
But the repeated issue is bigger than tie-breaking inside one core. The same few entries dominate across many cores. So salt tie-break is useful, but it should be part of a broader final-pack diversity picker, not the whole solution.
Best implementation direction
Use a two-layer fix:


Near-tie salt rotation within each core
This gives regenerate a chance to vary close winners.


Final selected-pack diversity pass across cores
This prevents the same anchor/domain/entry cluster from filling the batch repeatedly.


That is better than K=2 because it addresses what the audit actually found: not candidate shortage, but cross-core concentration around the same high-scoring pack entries.
